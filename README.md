# Keitaro API Wrapper

Создание кампаний и редактирование офферов через Keitaro Admin API.

**Стек:** FastAPI, SQLAlchemy, SQLite, Alembic, pytest, Angular, TypeScript.


## Возможности

- Создание кампании с доменом, группой и источником.
- Два потока: указанная страна → Google, остальные → выбранный оффер.
- Загрузка потоков, добавление, удаление и восстановление офферов.
- Закрепление долей и автоматический пересчёт остальных.
- Локальный черновик с публикацией в Keitaro или отменой изменений.
- Сохранение удалённых привязок в локальном архиве.
- При публикации текущие фильтры, лендинги и схема потока передаются без изменений вместе с обновлённым списком офферов.
- После публикации контрольный запрос проверяет состав офферов, их доли и состояния. При несовпадении черновик не помечается опубликованным.

## Запуск backend

Требуются Python 3.10+ и доступ к Keitaro Admin API.

Из корня проекта:

```bash
cd backend
```

**Linux / macOS:**

```bash
python3 -m venv .venv
source .venv/bin/activate
cp .env.example .env
```

**Windows PowerShell:**

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
Copy-Item .env.example .env
```

Заполните `backend/.env`:

| Переменная | Значение |
|---|---|
| `KEITARO_BASE_URL` | Адрес Keitaro без `/admin_api/v1` |
| `KEITARO_API_KEY` | Ключ Admin API |
| `KEITARO_DOMAIN_ID` | ID домена |
| `KEITARO_GROUP_ID` | ID группы кампаний |
| `KEITARO_TRAFFIC_SOURCE_ID` | ID источника |
| `CAMPAIGN_PREFIX` | Префикс названий, например `test_ivanov_` |

С активированным окружением установите зависимости, **примените миграции** и запустите сервер:

> [!IMPORTANT]
> Сначала заполните `backend/.env` реальными значениями и только потом
> запускайте `alembic upgrade head` — конфигурация проверяется при старте Alembic.

```bash
python -m pip install -r requirements.txt
alembic upgrade head
python -m uvicorn app.main:app --reload
```

SQLite создаётся в `backend/keitaro.db`. После изменения `.env` перезапустите сервер.

**Swagger:** `http://127.0.0.1:8000/docs`

## Запуск frontend

Требуются Node.js и npm, совместимые с версией Angular в `frontend/package.json`.

В отдельном терминале из корня проекта:

```bash
cd frontend
npm ci
npm start
```

**Интерфейс:** `http://localhost:4200`

Angular proxy перенаправляет `/api` на `http://127.0.0.1:8000`.
Для локального запуска `SERVER_URL` в `frontend/src/app/settings/settings.ts`
должен быть пустой строкой. Ключ Keitaro хранится только на backend.

## Использование

**Создание:** введите название с настроенным префиксом, код страны
(например, `AU`), выберите оффер и нажмите «Создать кампанию».

**Редактор:** введите ID своей кампании и нажмите «Загрузить потоки».
Изменения сохраняются локально. «Опубликовать» отправляет их в Keitaro,
«Отмена» возвращает последнее известное опубликованное состояние.

Закрепления и архив хранятся в SQLite. Удаление привязки не удаляет сам
оффер из Keitaro. Удаление последнего активного оффера запрещено.

## Тесты

Из `backend` с активированным окружением:

```bash
python -m pytest -q
```

Проверяются действия редактора, пересчёт долей, публикация, обработка
ошибок и архивация привязок. Используются прямые вызовы обработчиков,
SQLite в памяти и подмена ответов Keitaro — без изменения реального стенда.
HTTP-маршрутизация и сериализация ответов этими тестами не покрываются.

## Ограничения и проверка

- На реальном стенде проверены создание кампании, загрузка потоков и
  публикация с одним доступным оффером. Сценарии с несколькими офферами
  проверены автоматическими тестами: на стенде был доступен только один.
- При частичном создании кампания автоматически не удаляется.
  После тайм-аута проверьте Keitaro перед повторной отправкой.
- Собственной авторизации нет. Префикс ограничивает работу с кампаниями,
  но не заменяет авторизацию. Приложение предназначено для локального запуска.
